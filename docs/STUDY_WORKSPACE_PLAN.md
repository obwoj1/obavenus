# Study workspace parity

Obavenus is an original desktop product. This plan uses the visible Talvra workflow at `hwrk.help` as a feature reference; it does not copy Talvra's source, assets, or private service endpoints.

## Capabilities observed

- A study dashboard with due-soon, overdue, review, and today's-plan summaries.
- Course spaces containing modules, files, assignments, and course-specific study materials.
- Assignment pages that summarize instructions, requirements, grading criteria, skills, questions for the instructor, related documents, and a step plan.
- An AI homework workspace that creates and refines a draft, attaches deliverable files, and supports review before the student submits it themselves.
- Search across course documents with page-level references, plus a question-and-answer mode grounded in those documents.
- Study aids made from course files: notes, flashcards, and quizzes, followed by a spaced-review queue.
- Due-date reminders, quiet hours, a daily digest, and a study plan.
- An MCP endpoint for using study material from compatible AI clients, with a user-controlled hand-in boundary.

## Existing Obavenus building blocks

Obavenus already reads PDF, Word, Excel, and PowerPoint text locally, OCRs scanned PDFs, keeps encrypted per-project memory and conversation history, streams selected-provider responses, schedules local agent work, creates Office artifacts, and exposes an MCP-like tool workflow internally. These are reusable foundations, not proof that the study features below are complete.

## Implementation order

1. Build an optional local Study space: courses, assignments and due dates, checklists, notes, imported study files, and local search. Keep state encrypted and files on this Mac.
2. Add study-aid workflows over selected local files: explain with citations to page/slide, make notes, generate and edit flashcards, quiz mode, and a spaced-review queue. Use the configured provider or local Ollama; keep source references with generated content.
3. Add assignment support: requirement extraction, a student-editable plan and draft, artifact generation, and a review checklist. Do not submit work automatically.
4. Add optional external integrations with clear scopes and per-connection controls: Canvas, compatible MCP services such as Cengage where the school exposes a supported connector, then email reminders/digests.

## Current status

Obavenus now has an encrypted local Study interface for courses, assignments with editable plans and review checklists, due dates, encrypted local assignment attachments, notes, flashcard decks, deterministic spaced review, multiple-choice practice quizzes, and a persistent daily focus list populated from assignment steps. Opt-in once-per-deadline desktop reminders run while the app is open; configurable quiet hours defer near-deadline notifications until the quiet window ends. A local digest draft summarizes overdue and upcoming assignments, unfinished steps, and cards due; users can copy it, save it as a Gmail draft, or opt into a daily schedule that creates one Gmail draft per day while Obavenus is running. The schedule honors quiet hours and never sends email. Assignment instructions can draft deduplicated checklist steps, scan for explicit deliverables, quantities, output formats, citation styles, grading criteria, and explicitly named skills; they also surface clearly labeled instructor questions for requirements that appear unspecified and seed an editable assistant prompt with matching local course excerpts and selected assignment files. Assignment review checklists are seeded from detected requirements and rubric text, with a final student verification step. Assignment drafts persist encrypted, can receive a selected assistant response, and export to Word for review. Assistant responses can also be saved as encrypted Study notes, revised or deleted, and exported as Word documents. The scan and retrieval are local and labeled for user review. Generic starter checklist steps are clearly labeled when instructions have no detected actions. Canvas can be connected with a personal access token encrypted using the operating-system credential store; sync imports active courses, assignments, module/item metadata, and accessible files linked from course modules. Canvas updates preserve local assignment drafts and attachment references. Canvas file downloads are capped at 10 MB each and 20 MB per sync, external signed-download hosts never receive the Canvas bearer token, and matching files update only when Canvas reports a new revision. Course files can be searched within a selected course or across the library with deterministic term ranking. A grounded question action retrieves up to six bounded excerpts, labels page/slide citations, marks source text as untrusted, and prepares an editable chat prompt that is not sent until the student submits it. Remote MCP services can be connected with an optional bearer token; read-only server tools and advertised resources/templates are made available directly, while other server tools require an exact-argument native approval for every call over Streamable HTTP, with compatibility for the previous session-based protocol. A separate opt-in MCP server exposes read-only local Study tools and course-file resources to compatible clients; it binds only to IPv4 loopback, requires an OS-encrypted bearer token, and leaves drafts, Canvas credentials, and submission actions inaccessible. The built-in Canvas connector does not submit work; MCP write actions are shown for individual approval and a declined action is not sent. Imported files can produce an extractive local outline and deterministic flashcards. Assistant Markdown rendering is in place as a foundation for readable cited answers and structured drafts.
